LAB 3: MULTI-CLIENT CHAT APPLICATION
====================================

QUESTION
--------
Aim: To make a client–server application for chat, that is, a program in which many clients join one server and exchange messages with each other.

FILES
-----
- chat_server.py: binds 127.0.0.1:5050, starts one thread per client and broadcasts every message to the other clients.
- chat_client.py: sends your name first, then one thread receives messages while the main thread sends what you type.

LOGIC (HOW THE PROGRAM WORKS)
-----------------------------
chat_server.py
1. Keep a shared dictionary clients = {socket: name}, protected by a threading.Lock.
2. bind() to 127.0.0.1:5050, listen(), then loop forever on accept().
3. For every new client, start a new thread running handle_client(); the main thread goes straight back to accept().
4. handle_client(): the first message received is the client's name. Add it to the dictionary (under the lock) and broadcast "*** name joined the chat ***".
5. Then loop: recv() a message. If it is empty or "/quit", leave the loop. Otherwise print it and broadcast "[name] text" to everyone else.
6. When the client leaves: remove it from the dictionary, close its socket, and broadcast "*** name left the chat ***".
7. broadcast(): under the lock, send the message to every client except the sender.

chat_client.py
1. Ask for a name, connect() to the server and send the name.
2. Start a background thread that keeps calling recv() and prints whatever arrives.
3. The main thread keeps reading input ("you> ") and sending it. "/quit" ends the chat.
Because sending and receiving run in different threads, messages can arrive while you are typing (full duplex).

HOW TO RUN
----------
Open three terminals in this folder:
python3 chat_server.py     # Terminal 1
python3 chat_client.py     # Terminal 2 (name: alice)
python3 chat_client.py     # Terminal 3 (name: bob)
Type /quit in a client to leave. The server keeps running.

VIVA QUESTIONS
--------------
Q1. How does the server handle many clients at once?
A:  After accept(), it starts a new thread for each client and goes straight back to accept(), so it is always ready for the next client.

Q2. What is broadcasting here?
A:  When one client sends a message, the server sends it to every other connected client.

Q3. Why is a lock (threading.Lock) used?
A:  The clients dictionary is shared by all threads. The lock stops two threads from changing it at the same time (a race condition).

Q4. Why does the client use two threads?
A:  One thread only receives and prints; the main thread only reads input and sends. So it can send and receive at the same time (full duplex).

Q5. Thread vs process?
A:  Threads of one process share memory, so they are lighter and can share the client list. Processes have separate memory.

Q6. What happens when a client types /quit?
A:  Its server thread removes it from the list, closes the socket and tells the others it left; the other clients continue.

Q7. What is a daemon thread?
A:  A background thread that does not stop the program from exiting (daemon=True).

Q8. How could clients on other PCs join?
A:  Bind the server to the machine's LAN IP (or 0.0.0.0) and have the clients connect to that IP.
