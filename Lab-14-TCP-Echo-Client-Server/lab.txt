LAB 14: TCP/IP ECHO CLIENT–SERVER
=================================

QUESTION
--------
Aim: To implement, test, and benchmark a concurrent multi-threaded TCP/IP Echo Client and Server application using Python's Berkeley Sockets API, evaluating full-duplex stream I/O, delimiter-based framing, and Round-Trip Time (RTT).

FILES
-----
- tcp_echo_socket.py: Multi-threaded TCP echo server and client in one program, with echo checks and RTT measurement.

LOGIC (HOW THE PROGRAM WORKS)
-----------------------------
tcp_echo_socket.py (server and client in one program)
Server
1. Create a TCP socket, set SO_REUSEADDR, bind() to 127.0.0.1:65432, listen(10).
2. A background thread loops on accept(); every client gets its own handler thread.
3. Handler: recv() data into a buffer. While the buffer contains a newline, cut off one message and send it straight back with the newline (echo). Count the bytes echoed (under a lock).
Client
1. Connect to the server.
2. For each message: add "\n" (message boundary), start a timer, sendall(), and recv() until a newline comes back. Stop the timer: that time is the RTT.
3. Compare the echoed text with the sent text (MATCH / MISMATCH).
Demo
1. Phase 1: one client sends 5 messages and prints each echo and its RTT.
2. Phase 2: 4 client threads at the same time, 3 messages each; print each one's average RTT and the total bytes echoed. Then stop the server.

HOW TO RUN
----------
No input is needed; the test data is built into each program.
python3 tcp_echo_socket.py

VIVA QUESTIONS
--------------
Q1. What does an echo server do?
A:  It sends back exactly what it receives. It is used to test connections and measure round-trip time.

Q2. What is RTT?
A:  Round-Trip Time: the time from sending a message until its reply comes back.

Q3. Why does the server use threads?
A:  So several clients can be served at the same time; each connection gets its own thread.

Q4. What is message framing, and why does TCP need it?
A:  TCP is a byte stream with no message boundaries, so a delimiter (such as a newline) marks where each message ends.

Q5. What is SO_REUSEADDR?
A:  A socket option that lets the server bind the same port again right after it restarts.

Q6. What does listen(10) mean?
A:  Up to 10 incoming connections can wait in the queue before accept() takes them.

Q7. What is full duplex?
A:  Data can flow in both directions at the same time on one TCP connection.

Q8. Which address and port does the server use here?
A:  127.0.0.1 (loopback), port 65432.
